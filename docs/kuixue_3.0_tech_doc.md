## 一、完整技术路径

### 1.1 系统架构：8层决策引擎

```
┌─────────────────────────────────────────────────────┐
│                   出招表输出                          │
│              (方向 + 时机 + 个股 + 仓位)              │
├─────────────────────────────────────────────────────┤
│  P7 书籍哲学层  │  9条哲学 → 6条已集成，3条休眠      │
├─────────────────────────────────────────────────────┤
│  P6 方向细分层  │  12方向 → 83概念 → 231个股         │
├─────────────────────────────────────────────────────┤
│  P5 二阶效应层  │  间接利好（使能效应 > 直接效应）    │
├─────────────────────────────────────────────────────┤
│  P4 政策评分层  │  四维评分（财政/考核/时间表/举国体制）│
├─────────────────────────────────────────────────────┤
│  P3 历史类比层  │  60事件回测数据库                   │
├─────────────────────────────────────────────────────┤
│  P2 供应链层    │  6条传导链（政策→咽喉→核心→下游）   │
├─────────────────────────────────────────────────────┤
│  P1 政策生命周期│  5阶段（酝酿→发布→细则→资金→业绩）  │
├─────────────────────────────────────────────────────┤
│  数据管道       │  efinance + baostock（本地运行）     │
└─────────────────────────────────────────────────────┘
```

### 1.2 信号→操作全流程

```
政策事件输入
    │
    ├─① P4可信度评分（<3.0 → 拦截，不入场）
    │      四维：财政配套(0.25) + 地方考核(0.25) + 时间表(0.20) + 举国体制(0.30)
    │      spec_bonus：中办国办+0.5 / 国务院令+0.4 / 国发+0.3
    │
    ├─② E1 方向匹配（政策锚点 × 投资方向矩阵）
    │      8方向×多政策锚点，2年回测验证匹配度
    │      错配=亏钱（双碳→半导体亏11%，AI→新能源亏12%）
    │
    ├─③ E2 基本面筛选（个股级三条件 + PE过滤）
    │      ROE > 0 + 营收同比 > 0 + 负债率 < 70%
    │      PE按供应链位置分档：咽喉≤50 / 核心≤40 / 下游≤30 / 概念不碰
    │      负债率用assetToEquity反算（baostock直接字段不可靠）
    │
    ├─④ E3 时机判断（P1生命周期 + 大盘当日反应）
    │      酝酿期：P4≥3.5可轻仓25%
    │      发布期：HS300<1%可介入50%
    │      细则期：HS300<1%可加至100%
    │      资金期：仅50%以下
    │      业绩期：不入场
    │
    ├─⑤ L1 牛熊判断（最强防线）
    │      HS300 > MA250 → 牛市允许入场
    │      HS300 < MA250 + 6月低点反弹<15% → 熊市拦截
    │      3年熊市拦截17事件，14个正确
    │
    └─⑥ 17项清单逐项确认 → 出招表
           任一项不通过 = 不操作
```

### 1.3 数据管道

| 组件 | 技术 | 输出 | 频率 |
|------|------|------|------|
| efinance | Python本地 | A股行情5842只/涨停/换手率/龙虎榜 | 周一至五15:30 |
| baostock | HTTP(绕SSL) | 财报/负债率/ROE | 按需 |
| SQLite | kuixue_history.db | daily_snapshot / stock_daily / billboard | 自动 |
| 任务计划 | Windows Task | KuixuePipeline | 自动 |

### 1.4 交易执行规则

**入场**: E1+E2+E3三环全过 → 17项清单逐项确认 → 出招
**仓位**: 单方向≤5% / 总出招表≤30% / 分批建仓(50%→100%)
**止损**: 个股-15%无条件卖出
**持仓**: 最短2年，逻辑未破可延至3-5年
**等待**: 70%指数ETF + 30%现金等信号

## 二、风险评估

### 2.1 系统性风险（不可控）

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 政策方向逆转 | 低 | 逻辑全破(X3触发) | 减仓50%，观察1月 |
| 牛熊转换(L1) | 中 | 熊市拦截所有信号 | L1已验证：3年熊市14/17拦截正确 |
| 黑天鹅(地缘/疫情) | 低 | 全市场暴跌 | 30%现金缓冲+指数ETF底仓 |
| 流动性危机 | 极低 | 卖不出 | 个股选日均成交>5000万 |

### 2.2 模型风险（可量化）

| 风险 | 现状 | 量化依据 | 严重度 |
|------|------|----------|--------|
| **样本量不足** | 60事件仅7通过，4有收益 | 统计显著需>100次 | 🔴 高 |
| **胜率虚高** | 75%胜率基于4次操作 | 4/4不具统计意义 | 🔴 高 |
| **P4偏保守** | 拦截了多个正收益事件 | 央行577/创业投资P4<3但正收益 | 🟡 中 |
| **超额收益弱** | 3次盈利仅1次跑赢ZZ500 | 指数内垃圾股稀释α | 🟡 中 |
| **E2筛选牛市跑输** | 大基金三期E2+27.5% vs 全部+48.8% | 牛市垃圾股也涨 | 🟡 中 |
| **数据源不稳定** | 本机SSL异常+东财限频 | VPN/网络依赖 | 🟡 中 |
| **负债率数据不可靠** | baostock字段3次踩坑 | 需反算验证 | 🟢 低(已有方案) |

### 2.3 行为风险（最危险）

| 风险 | 表现 | 历史教训 | 防线 |
|------|------|----------|------|
| **等不及** | 信号来了就操作，不等E3 | v2.6追涨-28% | W1/W2等待规则 |
| **降低标准** | "差不多就行" | 16项清单只跑4项就出结论 | F6禁止降标 |
| **追涨** | 政策日大盘暴涨后买入 | v3回测负超额-0.89~-3.64% | F1/F2禁止追涨 |
| **频繁调参** | 回测不好就改规则 | 过拟合=实盘必亏 | 样本量<100不改规则 |

### 2.4 风险等级总评

```
整体风险: 🔴 高（验证不充分）

原因：
1. 实盘0次 / 模拟盘8天 / 回测4次有效操作 → 样本严重不足
2. P4/L1/E2参数未经过跨牛熊周期压力测试
3. 系统最脆弱的不是模型，是操作者（你自己说"等不了是最大的风险"）

可接受条件：
- 模拟盘运行≥6个月，经历≥3个信号
- 6个月结束后胜率≥50%，最大回撤<20%
- 操作期间0次违反等待规则
```

## 四、模型构建模型

### 4.1 元模型：如何构建和迭代量化模型

葵雪3.0的"模型构建模型"不是某一个策略，而是一套**从假说到验证到上线**的完整方法论：

```
┌──────────────────────────────────────────────────────┐
│                 模型构建元模型                         │
│                                                      │
│  ① 假说生成    ← 书籍/政策/经验 → 可证伪命题          │
│  ② 反例优先    ← 先找为什么错，再找为什么对            │
│  ③ 最小回测    ← 样本量>10000，跨牛熊，≥1年           │
│  ④ 证伪循环    ← 正收益=市场β？对比基准               │
│  ⑤ 参数锁定    ← 通过验证后锁死，不改                 │
│  ⑥ 模拟观察    ← ≥6个月，经历≥3信号                  │
│  ⑦ 小额实盘    ← ≤5%资产，严格止损                   │
│  ⑧ 复盘迭代    ← 每季度复盘，偏差归因                │
│                                                      │
│  ⚠️ 任何一步跳过 = 前功尽弃                           │
└──────────────────────────────────────────────────────┘
```

### 4.2 每一步的硬规则

| 阶段 | 硬规则 | 血泪来源 |
|------|--------|----------|
| 假说生成 | 必须可证伪，不说"可能涨" | — |
| 反例优先 | 先找3个反例再找1个正例 | v2.6只看正例→-28% |
| 最小回测 | >10000样本+跨牛熊+≥1年 | 3月回测正收益→1年-28% |
| 证伪循环 | 对比中证500(不是沪深300) | 沪深300是错误基准 |
| 参数锁定 | 样本<100不改规则 | 频繁调参=过拟合 |
| 模拟观察 | ≥6个月+≥3信号+0违规 | 模拟1天就想操作 |
| 小额实盘 | ≤5%资产 | 急于加仓 |
| 复盘迭代 | 偏差归因，不改参数改逻辑 | 调参数掩盖问题 |

### 4.3 当前系统在元模型中的位置

```
假说生成 ✅ → 反例优先 ✅ → 最小回测 ✅ → 证伪循环 ✅ → 参数锁定 ⚠️ → 模拟观察 🔴 → 小额实盘 ❌ → 复盘迭代 ❌

当前位置：参数锁定阶段（P4/E2/L1参数基本锁定，待模拟盘验证）
下一关卡：模拟盘运行至2026-10-28，至少3个信号验证
```

### 4.4 模型失效判据

以下任一触发 = 模型失效，回到假说阶段：

1. **模拟盘6个月胜率<40%** — 系统不如随机
2. **连续3次止损** — 入场逻辑系统性错误
3. **6个月整体亏损>15%** — 比买入持有更差
4. **发现根本性逻辑漏洞** — 如P4评分维度遗漏关键因子
5. **市场结构发生根本变化** — 如A股退市制度彻底改变α来源

### 4.5 与传统量化模型的关系

| 维度 | 传统量化 | 葵雪3.0 |
|------|----------|---------|
| 信号源 | 价量/技术指标 | 政策文本+基本面 |
| 选股逻辑 | 因子模型 | 自上而下(政策→方向→个股) |
| 持仓周期 | 日/周 | 2-5年 |
| 回测基准 | 沪深300 | 中证500(β=1.49) |
| α来源 | 统计套利 | 政策定价时差 |
| 最大风险 | 过拟合 | 等不及/降标准 |
| 验证标准 | Sharpe>2 | 胜率>50%+超额>0 |

### 4.6 为什么不叫"策略"而叫"模型构建模型"

因为葵雪3.0的核心不是某一个策略参数组合，而是一套**生成策略的方法论**：

- 策略会失效（市场适应后α消失）
- 方法论不会失效（只要政策驱动的A股逻辑不变）
- 具体策略（P4阈值3.0还是3.5、PE上限40还是50）是**参数**
- 决定用什么参数、何时调整参数的**规则**才是模型

**一句话**：策略是产品，元模型是生产线。产品会过期，生产线不会。
